# π0.5 M1000 QY2 D72 FlashAttention 迁移与端到端适配设计

**状态：已获用户确认，待实现**  
**日期：2026-11-18**  
**范围：M1000 / MP22 / π0.5 vision attention / BF16 D72 FA**

## 1. 目标与非目标

目标是把已经能够独立加载和运行的 QY2 D72 BF16 FlashAttention module 接入 APXInf 的 MUSA adapter，并完成：

1. standalone QY2、APXInf adapter、CPU reference 的同输入数值对照；
2. adapter 的 module、function、context、stream、LSE 和 descriptor 生命周期管理；
3. eager repeated-call 与 graph capture/replay；
4. π0.5 vision block 和 L1 路径的端到端 correctness A/B；
5. muDNN FA 与独立 QY2 FA 的延迟、显存和 kernel 数对照。

本轮不修改 Qwen3.8/GDN、S5000 路径、π0.5 INT8 GEMM/TileLang GEMM，也不复制 muDNN 中标记为 proprietary/confidential 的源码。独立 FA 只使用已授权的构建产物、公开接口、APXInf 自有 adapter 和 clean-room 的调用契约。

## 2. 固定 contract

π0.5 vision D72 contract 固定为：

```text
B = 2
S_q = S_k = 256
H_q = H_kv = 16
D = 72
dtype = BF16
mask = none
causal = false
layout = [B, S, H, D]
```

对应连续布局参数：

```text
batch_stride = S * H * D = 294912 elements
seq_stride   = H * D     = 1152 elements
head_stride  = D         = 72 elements
kv_heads     = 16
head_offset  = 0
head_group   = 1
```

contract test 必须复用同一组 Q/K/V 输入，依次比较：

```text
CPU float64 reference
standalone QY2 module launch
APXInf D72 adapter
```

比较 output、LSE、有限值和必要的中间参数；禁止只用端到端最终 cosine 推断 ABI 正确。

## 3. 组件与数据流

### 3.1 Standalone probe

保留一个最小、可重复的 standalone probe，负责验证 module image、function symbol、launch ABI 和 CPU reference。probe 不依赖 APXInf Python wheel，不使用旧 debug wheel，不混用旧的 context 或输入 dump。

### 3.2 APXInf D72 adapter

新增或扩展独立 D72 adapter，职责仅包括：

- 加载和缓存 QY2 module/function；
- 将 APXInf Tensor 指针和 shape 转换为 QY2 launch contract；
- 管理 LSE 与必要 scratch；
- 在调用前绑定当前 MUSA runtime stream 对应的 driver context；
- 提供稳定的 Rust/PyO3 可调用 ABI；
- 返回明确的 MUSA error，不静默 fallback。

优先使用生成器产出的 host wrapper，以避免手写 `muLaunchKernel(void** params)` 的 robust pointer/参数数组 ABI。只有 host wrapper 无法满足 APXInf 生命周期要求时，才保留手写 launch，并以 standalone probe 的参数布局作为唯一来源。

### 3.3 生命周期

缓存键至少包含 device 和 module variant；若 descriptor 或 LSE 与 stream/context 有关，则缓存键必须包含相应 stream/context 信息。规则如下：

- 首次调用完成 module 加载、function 解析和必要 buffer 分配；
- graph capture 前完成所有首次初始化；
- capture 期间不调用可能分配或加载 module 的路径；
- 相同 shape 的 repeated call 复用 descriptor、LSE 和 scratch；
- destroy/recreate 后不得使用失效 function、module 或 buffer；
- context 不得只按线程缓存，必须校验当前 device/stream 对应 context；
- LSE allocator 先与 standalone probe 对齐，必要时使用 Driver API `muMemAlloc`，并记录释放策略。

## 4. 分阶段验收

### Gate A：基线与隔离

在 m1000 的 `feat/tilelang-framework` 工作树上建立独立工作分支，例如 `feat/pi05-m1000-qy2-d72-fa`。记录 commit、wheel、QY2 image/fatbin、probe 和 checkpoint 的 SHA-256。所有临时脚本、日志、dump、trace 放在 `devlocal/pi05-m1000-qy2-d72-fa/`。

### Gate B：adapter contract

通过以下测试才进入端到端：

- standalone 与 CPU reference cosine/relative L2 通过；
- APXInf adapter 与同一 reference 通过；
- output/LSE 无 NaN/Inf；
- 参数、stride、context、module/function 与 standalone 对齐；
- 同 shape repeated call 结果稳定；
- reset/destroy/recreate 不复用失效资源；
- 错误 shape、dtype、device 能明确拒绝。

### Gate C：graph

先在固定 D72 shape 下做 graph capture/replay：

- capture 前预热并完成 module/function/LSE/descriptor 初始化；
- replay 多次结果与 eager 一致；
- capture 期间无首次分配、module load 或 descriptor 创建；
- graph destroy/recreate 后资源仍有效或明确重建。

### Gate D：π0.5 端到端

增加实验选择项：

```text
APXINF_PI05_FA=mudnn
APXINF_PI05_FA=qy2
APXINF_PI05_FA=auto
```

初始默认保持现有 muDNN 路径。`qy2` 用于强制独立路径，`auto` 只有在 D72 contract 和初始化成功后才选择独立路径，否则明确记录回退原因并走 muDNN。验证 vision block、L1 forward、graph replay 和完整 output 的数值一致性。

### Gate E：性能与显存

统一测试以下三条路径：

1. muDNN QY2 native FA；
2. APXInf 独立 QY2 D72 FA；
3. 已知 fallback/disabled 路径。

分别记录 standalone FA、vision block、π0.5 L1 的 P50/P95/mean、首次调用和 steady-state；记录峰值显存、持久化 buffer、workspace、kernel launch 数。性能结论必须区分首次编译/加载与稳态 replay。

## 5. 错误处理与回退

- QY2 image 缺失、symbol 缺失、context 不匹配、shape 不支持都必须返回带 variant/shape 的错误；
- 不允许把 NaN output 当作成功；
- `auto` 模式可以回退到 muDNN，但必须打印结构化原因；
- `qy2` 强制模式不能静默回退；
- fallback 路径不能被误标成独立 QY2 性能结果。

## 6. 维护范围

预计维护代码集中在：

- `crates/apxinf-musa/adapters/` 的 D72 module adapter；
- `crates/apxinf-musa/src/ffi/` 的声明和资源句柄；
- `crates/apxinf-musa/src/kernels/attention.rs` 或独立 D72 facade；
- π0.5 model/backend 的 FA 选择开关；
- contract/integration tests；
- `devlocal/pi05-m1000-qy2-d72-fa/` 下的实验产物。

不修改现有 MP22 D256 FA 的 ABI 和默认 dispatch，除非 contract test 证明共享抽象存在明确且无回归的必要性。
